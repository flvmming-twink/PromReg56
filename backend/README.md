# ИС социально-экономического развития

Приложение использует PostgreSQL и загружает реальные предприятия, показатели и источники из `db.sql`. Драйвер `psycopg` 3 устанавливается из `requirements.txt`; отдельно устанавливать `psycopg2` не нужно — драйвер не заменяет сам сервер PostgreSQL. SQLite и Docker для запуска приложения не используются.

## Подготовка PostgreSQL в Windows

Установите PostgreSQL 18 и Command Line Tools через официальный установщик PostgreSQL. В установщике запомните пароль пользователя `postgres` и оставьте включённым компонент `Command Line Tools`. Если команда `psql` не находится, добавьте каталог PostgreSQL `bin` в `PATH` (например, `C:\Program Files\PostgreSQL\18\bin`) и откройте новое окно PowerShell.

Проверьте, что сервер запущен и команды доступны:

```powershell
Get-Service *postgres*
psql --version
```

Если служба остановлена, запустите её из приложения «Службы» Windows. Задайте параметры подключения и запустите безопасный импорт готового дампа:

```powershell
$env:POSTGRES_DB = "regional_economy"
$env:POSTGRES_ADMIN_URL = "postgresql://postgres:ВАШ_ПАРОЛЬ@localhost:5432/postgres"
$env:DATABASE_URL = "postgresql://postgres:ВАШ_ПАРОЛЬ@localhost:5432/regional_economy"
.\setup-postgres.ps1
```

Скрипт создаёт базу, если её ещё нет, и импортирует `db.sql` только в пустую базу. Если в целевой базе уже есть таблицы, импорт остановится без изменений. Не удаляйте непустую базу ради повторного импорта: используйте отдельную новую базу или сначала сделайте резервную копию. Файл `data.sqlite3` — оставшаяся локальная SQLite-база; приложение его не использует. Текущий набор проверенных данных берётся из PostgreSQL-дампа `db.sql`.

Если пароль содержит специальные символы (`@`, `:`, `/`, `%`), замените их URL-кодированными значениями в обеих строках подключения. Для удалённого сервера укажите его адрес в `POSTGRES_ADMIN_URL` и `DATABASE_URL`.

## Запуск приложения

Для карты получите ключ JavaScript API Яндекс.Карт в кабинете разработчика Яндекса. В PowerShell из каталога проекта задайте ключ и пароль PostgreSQL в URL, затем запустите Flask:

```powershell
$env:YANDEX_MAPS_API_KEY = "ВАШ_КЛЮЧ_ЯНДЕКС_КАРТ"
$env:DATABASE_URL = "postgresql://postgres:ВАШ_ПАРОЛЬ@localhost:5432/regional_economy"
.\.venv\Scripts\python.exe app.py
```

Откройте `http://127.0.0.1:5101`. Для показа карты нужен действительный `YANDEX_MAPS_API_KEY`; если он не задан, приложение покажет подсказку. Если пароль содержит специальные символы (`@`, `:`, `/`, `%`), замените их URL-кодированными значениями в `DATABASE_URL`. По умолчанию приложение подключается к `postgresql://postgres:postgres@localhost:5432/regional_economy`; при другом пароле обязательно задайте переменную окружения.

Для входа администратора по умолчанию используйте логин `admin` и пароль `admin123`. Для рабочего окружения задайте `ADMIN_LOGIN`, `FLASK_SECRET_KEY` и один из параметров `ADMIN_PASSWORD_HASH` или `ADMIN_PASSWORD`.

Отчёты формируются только после входа администратора, сохраняются в PostgreSQL и доступны для скачивания всем посетителям в формате Excel (`.xlsx`). Таблица отчётов создаётся автоматически при первом обращении. Кнопка с колокольчиком включает и выключает всплывающие уведомления в текущем браузере.

## Публикация в интернете через GitHub и Render

GitHub хранит исходный код, а Render запускает Flask-приложение и PostgreSQL. GitHub Pages для этого проекта не подходит: он не запускает Python-сервер и базу данных. Файл `render.yaml` настраивает веб-сервис и базу данных автоматически.

1. Создайте пустой репозиторий на GitHub. Не добавляйте к нему README или другие файлы, если проект уже содержит их.
2. Из каталога проекта выполните команды, заменив адрес на URL своего репозитория:

   ```powershell
   git add .
   git commit -m "Prepare app for deployment"
   git remote add origin https://github.com/ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ.git
   git push -u origin main
   ```

3. Войдите на [Render](https://render.com), выберите создание нового Blueprint и подключите репозиторий. Render прочитает `render.yaml`. При настройке задайте `ADMIN_PASSWORD` (сильный пароль администратора) и `YANDEX_MAPS_API_KEY` (ключ карты).
4. После создания PostgreSQL откройте в Render страницу базы данных и скопируйте **External Database URL**. В PowerShell из каталога проекта выполните импорт дампа:

   ```powershell
   $env:DATABASE_URL = "ВНЕШНИЙ_DATABASE_URL_ИЗ_RENDER"
   psql "$env:DATABASE_URL" -v ON_ERROR_STOP=1 -f .\db.sql
   Remove-Item Env:\DATABASE_URL
   ```

   Для импорта нужен установленный PostgreSQL Command Line Tools (`psql`). Используйте именно внешний URL базы Render; не публикуйте его и не добавляйте в файлы проекта.
5. Дождитесь успешного завершения Deploy в Render. Адрес сайта будет показан в панели Render в формате `https://...onrender.com`; ссылку на исходный код можно будет открыть в репозитории GitHub.

Бесплатный веб-сервис Render может засыпать при отсутствии посетителей, а бесплатная база имеет ограничения по сроку хранения и доступности. Для постоянно работающего сайта и надёжного хранения данных выберите подходящие платные тарифы и регулярно сохраняйте резервные копии базы. Не публикуйте реальные пароли, ключи API или URL базы в GitHub.

## API

- `GET /api/health` — проверка приложения и PostgreSQL.
- `GET /api/companies` — список предприятий с последними опубликованными показателями.
- `GET /api/companies?search=металл` — поиск по названию предприятия.
- `POST /api/companies` — добавление предприятия в PostgreSQL; город и отрасль должны существовать в справочниках.
- `GET /api/sources` — источники со ссылками и датами из PostgreSQL.
- `GET /api/metrics/employment` — сумма опубликованной занятости по годам.
- `GET /api/metrics/territories` — опубликованные показатели по городам и годам.
- `GET /api/analytics?territory=Новотроицк&period=2021-2025&metric=revenue` — сводка, графики и данные предприятий для аналитической панели. Поддерживаются `revenue`, `employees` и `investments`; период можно указать как один год или диапазон.
- `GET /api/reports` — сформированные администратором отчёты.
- `POST /api/reports` — формирование и сохранение Excel-отчёта (только администратор).
- `GET /api/reports/<id>/download` — скачивание Excel-файла.
- `DELETE /api/reports/<id>` — удаление отчёта (только администратор).
- `GET /api/indicators` и `POST /api/indicators` — чтение и сохранение пользовательских показателей; таблица PostgreSQL создаётся автоматически.
- `POST /api/sources` — добавление источника после входа администратора.
- `POST /api/login` и `POST /api/logout` — вход и выход администратора.
