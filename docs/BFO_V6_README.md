# PromRegion56 — расширение БФО и численности персонала, v6

**Состояние: 22 ноября 2026 года.** Для репозитория https://github.com/flvmming-twink/PromReg56.

## Назначение

Добавить проверенные показатели бухгалтерской отчётности из e-ecolog.ru/buh/{ГОД}/{ИНН}, показать последний достоверно найденный год среднесписочной численности персонала, улучшить интерактивность графиков. Сохранить только города **Новотроицк, Орск и Оренбург** и период **2021–2025**. Никаких расчётных или вымышленных значений.

Исходный набор из 39 предприятий (15 + 19 + 5) **сохраняется**. На момент подготовки пакета первично подтверждены:

| Показатель | Что удалось подтвердить |
|---|---:|
| Всего действующих карточек в наборе | 39 |
| Предприятия с разобранной БФО e-ecolog | 8 |
| Отдельные финансовые значения, включая сравнения за предыдущие годы | 140 |
| Финансовые ряды с >=3 различными годами | 26 |
| Предприятия с подтверждённой среднесписочной численностью | 15 |
| Наблюдения численности за определённый год | 35 |
| Предприятия с рядом численности >=3 лет | 10 |
| URL для последующей проверки (не все содержат отчётность) | 195 |

**Ограничение:** сведения о БФО для всех остальных предприятий не подтверждены заново. CSV со всеми 195 URL — проверочный список, а НЕ 195 подтверждённых отчётов. Данные из прежней базы со статусом `pending` не становятся `verified` автоматически. Сведения о работниках извлечены из открытых карточек Firmoteka, где опубликована среднесписочная численность на основе сведений ФНС; они не взяты непосредственно из форм БФО.

## Содержимое

* `database/promregion56_bfo_v6_patch.sql` — **дополнительный PostgreSQL SQL** к текущему дампу (НЕ самостоятельный дамп). `CREATE TABLE IF NOT EXISTS`, индекс, представления, UPSERT 140 фактов финансов и 35 записей численности. Финансовые строки в `enterprise_metrics` обновляются при выполнении условий; сохраняется контроль ИНН и 3 городов. Отсутствующие значения не подменяются нулём.
* `financial_facts_verified.csv` — 140 значений с годом отчёта, исходными тысячами рублей и конвертацией в рубли.
* `workforce_verified.csv` — среднесписочная численность с указанием года, ИНН и источника.
* `all_39_companies_195_bfo_urls.csv` — план проверки по каждому ИНН за 2021–2025. Статус страницы указывает, удалось ли **извлечь и проверить** данные.
* `scripts/apply_frontend_patch.py` — идемпотентные изменения `app.js`, `styles.css`, `scripts/build-data.mjs`. Делает копии `*.v6-backup`.
* `scripts/parse_saved_eecolog.py` — **дополнительный офлайн-инструмент** для дальнейшего импорта по сохранённым законно доступным HTML-страницам отчётности. Строго требует совпадения ИНН, года, единиц измерения, кодов строк.
* `CODEX_PROMPT.md` — задание для Codex.
* `VALIDATION.md` — проверки и ограничители публикации.

## Установка в репозиторий для Codex

Не выкладывайте файлы без предварительной проверки в отдельной ветке.

1. Поместить файлы архива в корень проекта.
2. **Дополнить** `database/industrial_city_db.sql` содержимым `database/promregion56_bfo_v6_patch.sql` ПОСЛЕ последнего `COMMIT;` исходного дампа. Не подменять весь файл одним патчем.
3. Запустить `python scripts/apply_frontend_patch.py .` — изменит 3 файла; без успешного совпадения маркеров остановится с понятной ошибкой. Перед изменениями сохраняет резервные копии.
4. Запустить `node scripts/build-data.mjs` — перепишет статическую витрину `data.js` из объединённого SQL. GitHub Pages **не подключается** напрямую к PostgreSQL.
5. Проверить `node --check app.js` и `node --check data.js`, открыть сайт локально и выполнить сценарии из `VALIDATION.md`.
6. Не коммитить автоматически временные файлы `*.v6-backup`; после теста их можно перенести вне репозитория.

## Принцип 3 лет

Ряд отображается на графике только если известны значения **за минимум три различных календарных года в промежутке 2021–2025**. Это правило действует отдельно для `revenue`, `net_profit`, `assets`, `cost_of_sales`, `operating_profit`, `profit_before_tax`, `employees` и других показателей. Счётчик не рассматривает пять повторений одного года как пять значений. Пустые годы должны остаться пустыми; не делать прогноз и не считать отсутствующие данные нулём.

**Исключение — карточка последней численности:** если достоверно известна среднесписочная численность только за 2025 или 2024 год, карточка показывает именно этот год. Например, `Актуальное число сотрудников на 2024 год: 100 чел.` — с пометкой, что показатель относится к **году**, не к текущему дню. Если численность известна только из прежней непроверенной базы, выводить соответствующее предупреждение.

## Бухгалтерская отчётность и единицы измерения

Форма БФО на e-ecolog указывает **384 — тысяча рублей**. Исходная величина умножается на 1 000 при загрузке в `amount_rub`, поле `original_thousand_rub` сохраняет значение из источника. Код строки:

* `2110` — выручка;
* `2400` — чистая прибыль (включая убыток со знаком минус);
* `1600` — активы/итог баланса;
* `2120` — себестоимость продаж (для визуализации расходы положительной величиной с сохранением пометки);
* `2200` — прибыль/убыток от продаж;
* `2300` — прибыль до налогообложения.

БФО последнего года может включать сравнения за более ранние годы. Поля `report_year` и `source_year` разделены. При несовпадении первоначальных и переизложенных сравнительных данных в `note` хранится соответствующее уточнение. Разделять данные отдельного юрлица и его филиала/площадки.

## Источники

Для отображения в карточке предприятия — **не более двух ссылок** (отчётность + численность, если доступны; иначе из старого набора). В `eecolog_financial_facts.source_url` на каждом факте сохраняется точная форма отчёта, даже если для корректного аудита в пределах пяти лет понадобилось более двух разных редакций отчётности. Не смешивать данные разных ИНН.

## Безопасность

* Не использовать SQL-патч как полную базу, он работает только после существующего дампа.
* Сначала выполнять миграцию на копии PostgreSQL или в новой базе и проверять `VALIDATION.md`.
* При изменении основного `industrial_city_db.sql` повторно собирать `data.js` и публиковать ОБА файла в GitHub Pages.
* Автоматическая публикация на GitHub этим архивом **не выполняется**. PostgreSQL-проверка на реальном сервере не проводилась.
