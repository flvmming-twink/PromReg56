# PromRegion56 v7 — база для трёх городов, 2021–2025

**Дата пакета:** 22 ноября 2026 года. **Основание изменений:** файл Михаила «Отчёт по ошибкам в приложении для консолидации данных (2).docx», страницы 4–13, а также новое правило пользователя — не менее двух календарных лет с ненулевыми данными для каждого показателя.

## Состав

- **59 предприятий:** Новотроицк 16, Орск 19, Оренбург 24.
- **761 отдельных наблюдений** за 2021–2025 годы, **187 различных временных рядов** с двумя или более годами.
- **107 ссылок на основные источники** — 1–2 на компанию; дополнительно для каждой точки сохранён URL происхождения.
- **15 предприятий** с последней известной численностью работников.
- По сравнению с предыдущим набором из 39 предприятий добавлено 22 и исключено 2.

## Какие данные допускаются

Для графика нужны как минимум 2 разных календарных года, не 2 цифры в одном году. `NULL` и 0 исключены из рядов, положительные и отрицательные ненулевые значения учитываются. Количество лет может быть 2, 3, 4 или 5. Предприятие без хотя бы одного допустимого ряда исключается. Последнюю численность работников можно показать в отдельном поле за 1 год, только если само предприятие прошло общий фильтр по иным показателям.

### Надёжность данных

| Статус | Число точек | Значение |
|---|---:|---|
| `source_checked` | 136 | Извлечены бухгалтерские значения из предыдущего v6-пакета, с реестровым URL и ИНН |
| `eecolog_table` | 19 | Дополнительные значения из e-ecolog, в рублях после перевода из тысяч рублей |
| `workforce_registry` | 30 | Среднесписочная численность по реестровому источнику |
| `registry_rounded` | 218 | Таблицы ruИНН с округлением до 0,1 млн рублей; *не* точные до рубля |
| `registry_linked_pending` | 103 | Унаследованные значения с ссылками, самостоятельная повторная проверка ещё нужна |
| `legacy_pending` | 255 | Значения из прежнего набора, требуется проверка ИНН и источника |

Таким образом, прохождение порога двух лет **не означает**, что все 761 число прошли независимую сверку. В сравнении с исходным проектом сохранён принцип не придумывать неизвестные суммы. Инженерные Технологии (нулевой график) исключены.

### Замечания из отчёта Михаила

Добавлены расширенные статьи Новохрома, Уральской Стали, Оренбургского пропанта, НЗБП с явной точностью и источником. Для НСплава перечень желаемых статей из отчёта сам по себе не содержит минимум двух подтверждённых значений, поэтому новые числовые ряды по запасам/управленческим расходам/прочим доходам **не подставлялись искусственно**. Их можно включить после получения по меньшей мере двух значений за разные годы.

### Файлы

- `database/promregion56_v7_FRESH.sql` — полный SQL для **новой пустой** PostgreSQL-базы;
- `database/promregion56_v7_UPDATE_AFTER_V6.sql` — SQL-миграция для уже установленной версии v6;
- `data_v7.json` — источник отфильтрованной витрины данных, используемой статическим сайтом;
- `scripts/apply_v7_dataset.mjs` — накладывает отобранную витрину на `data.js` после `node scripts/build-data.mjs`;
- `scripts/apply_v6_hover_and_staff_ui.py` — патч для подсказок графиков и персонала, если он не установлен;
- `audit/*.csv` — аудит карточек, источников, числовых наблюдений;
- `audit/validation_summary.json` — контрольные показатели;
- `CODEX_INTEGRATION.md` — пошаговая интеграция и SQL-контроль;
- `CODEX_PROMPT.md` — короткое сообщение, которое можно отправить Codex;
- `VALIDATION.md` — тесты приёмки;
- `tests/validate_v7.mjs`, `tests/validate_v7.sql` — автоматические проверки JSON и PostgreSQL.

**Совместимость:** репозиторий `flvmming-twink/PromReg56` по состоянию на 22.11.2026, статическая витрина `data.js`, Node.js, PostgreSQL. Сборка тестировалась на имитации исходного `data.js`; исполнение полного SQL на настоящем PostgreSQL в этой сессии не выполнялось.

**Уточнение границ:** `МК ЖеЛеН` (ИНН 5635021122) расположен в селе Ударник, которое административно входит в городской округ Орск, но не является городом Орском. Поэтому объект **исключён** из набора, ограниченного только тремя городами.
