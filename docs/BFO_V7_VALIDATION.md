# Контроль качества и приёмка v7

## Результаты выполненных проверок

- Разные города: строго три — Новотроицк 16, Орск 19, Оренбург 24.
- Предприятий 59; из прежних 39 добавлено 22, исключено 2.
- Временных рядов 187; в каждом как минимум 2 **разных года** 2021–2025 с ненулевыми значениями.
- Годовых числовых точек 761, каждая привязана к предприятию, году, метрике и ссылке на источник.
- Источников для карточек 107, максимум 2 на предприятие.
- Поле последней среднесписочной численности доступно по 15 компаниям.
- Не допускаются пустые графики, нулевые искусственные ряды и дополнительные города.
- ОГРН нормализованы, ИНН имеют 10 или 12 цифр.

## Выполнено

1. Генерация SQL и JSON прошла без ошибок.
2. Проверены структура JSON, число лет каждого показателя, нулевые значения, уникальность ключей, ИНН, город и диапазон лет.
3. `node --check scripts/apply_v7_dataset.mjs` — проверка синтаксиса успешна.
4. Пробная сборка `data.js` на тестовой структуре старой витрины выполнена. Содержимое отфильтровано до 59 предприятий, 761 точек и 187 рядов.

## Что должен проверить Codex дополнительно

1. Исполнить SQL на новой или тестовой PostgreSQL-базе: `psql -v ON_ERROR_STOP=1 -f database/promregion56_v7_FRESH.sql` (только для чистой базы); для существующей v6 — альтернативная миграция UPDATE.
2. Исполнить SQL-запросы в `CODEX_INTEGRATION.md` и сравнить ожидаемые количества.
3. Проверить, что оригинальный `scripts/build-data.mjs` после дополнений сохраняет валидную структуру `data.js`, а `scripts/apply_v7_dataset.mjs` корректно завершает публикацию.
4. Убедиться, что все данные по компаниям отображаются в единицах измерения из `metric_definitions`, а округлённые помечены «≈».
5. Проверить `app.js`: mouseover, mouseleave, focus, blur точек всех графиков, в том числе отрицательные значения.
6. Валидация периода и нулей в UI: отсутствующие 2022/2024 не превращаются в 0, промежутки графика не должны изображать точное значение отсутствующего года.
7. Сохранены фильтры карты, карточки, поиск, продукты, мобильная верстка.
8. В публикации не должно быть данных других территорий. Счётчики главной должны показывать 59 и 3.
9. Если новый SQL применяется к уже существующей БД, проверить конфликты идентификаторов, внешние ключи и резервную копию.

**Требует внимания:** для НСплава отдельные новые статьи из отчёта Михаила ещё недостаточно подтверждены (менее 2 значений по найденным доступным источникам). Наследованные записи `pending` нельзя переименовывать в `verified`.

**Уточнение границ:** `МК ЖеЛеН` (ИНН 5635021122) расположен в селе Ударник, которое административно входит в городской округ Орск, но не является городом Орском. Поэтому объект **исключён** из набора, ограниченного только тремя городами.
